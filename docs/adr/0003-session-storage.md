# 会话存 SQLite 的不可变条目日志，不存 JSONL 文件

Pi 把会话存成按工作目录分组的 JSONL 树文件，追加写、无索引、恢复时全量读；chat-demo 用 IndexedDB 存会话、摘要与附件。我们已经有 SQLite 单库承载文章、词条、原句、钉住与学习进度，会话再单独落文件就会出现两份真源、跨表查询要扫文件、钉住与消息无法共用一笔事务。所以会话也在 SQLite 里，但**照搬 Pi 的语义**：条目只追加不改写，`id`/`parent_id` 构成树，线程只存一个 `leaf_id` 表示当前分支；超窗时追加一条 `compaction` 条目（摘要 + `first_kept_entry_id`），原文一条不删。

## Considered Options

- **Pi 的 JSONL 文件**：追加写、可读可 diff、整目录即备份，但列表要逐文件全读，按词条/文章查钉住没有连接，删除与备份要跨两种存储对齐。
- **每条线程存一整块 JSON**：写入简单，但编辑一条消息就要重写整条线程，跨线程查询只能靠 `json_each` 扫。
- **自动写 JSONL 镜像**：能保留“文件感”，但两份真源要对齐，首版不值得；改成按需导出。

## Consequences

- 分支切换是一行 `UPDATE thread SET leaf_id`；消息本身永不 UPDATE，改口就新建条目。
- 钉住是独立表，存复制出来的文本快照 + 出处（线程、条目、模型、命中的原句）+ 落点（词条 / 文章 / 未归档）；删线程、压缩、改消息都不影响已钉住的内容。
- 会话列表靠 `thread` 上的冗余列（消息数、首条摘要、更新时间）一次查询完成，不扫正文。
- 单条线程可导出为 JSONL（可读、可 diff、大致兼容 Pi 格式），但导出物不是真源。
- schema 迁移走显式版本号，不在加载时改写既有数据——这一点刻意不学 Pi。
